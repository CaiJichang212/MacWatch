## 1. 项目背景与 MVP 定位

MacWatch MVP 是一个面向 MacBook Air M 系列笔记本的本地温度监控工具。第一版只解决一个核心问题：让用户实时查看 CPU、GPU、内存、磁盘、电池这五类硬件中可读取的温度状态，并通过趋势图理解温度随时间变化的过程。

约定 MVP 版必须覆盖的温度硬件范围：
CPU、GPU、内存、磁盘、电池。

这里的“必须覆盖”表示 UI、能力检测、状态说明、历史数据模型和趋势查看都必须包含这五类硬件。CPU 温度是 MVP 在开发和验收机器 MacBook Air M4 上必须读到的有效指标；GPU、内存、磁盘、电池温度按设备支持状态展示，不可读取时必须明确显示 `unsupported` 或 `readFailed`，不能隐藏到用户无法感知。

MVP 不追求覆盖完整系统监控能力，不做 CPU、内存、磁盘 I/O、电池功耗等资源监控，也不做告警、导出、云同步、远程监控或风扇控制。其目标是先验证 Apple Silicon MacBook Air 上温度采集、低能耗实时刷新、本地会话历史记录和趋势可视化这条主链路是否稳定可用。

核心价值：

- 实时查看 MacBook Air M 系列设备的 CPU、GPU、内存、磁盘、电池关键温度。
- 回看本次 App 运行会话内的温度变化趋势。
- 识别高负载使用、充电、外接显示器、环境温度变化等场景下的温度波动。
- 明确显示每个温度指标的数据来源和支持状态。
- 默认本地处理数据，不上传任何设备指标。

## 2. 目标机型与兼容边界

### 2.1 MVP 目标机型

MVP 只考虑以下设备：

- MacBook Air M1/M2/M3/M4/M5。
- 后续 MacBook Air M 系列机型在能力检测通过时可兼容，但不作为 MVP 验收基准。
- 当前用于开发和验收此项目的设备是 MacBook Air M4。

### 2.2 不作为 MVP 验收对象的机型

以下设备不纳入 MVP 验收：

- Intel Mac。
- MacBook Pro。
- Mac mini、iMac、Mac Studio、Mac Pro。
- Hackintosh、虚拟机或非标准 macOS 环境。
- 外接硬盘、扩展坞、外置 GPU 等外部设备。

### 2.3 关键兼容假设

- MacBook Air M 系列通常无风扇，因此 MVP 不设计风扇转速、风扇异常、风扇控制能力。
- Apple Silicon 温度来源受 macOS 版本、芯片型号和系统接口变化影响，必须以运行时能力检测结果为准。
- 某些温度项在部分设备上可能不可读取，应用必须显示“不支持”或“读取失败”，不能伪造、推断或用空值误导用户。
- M1/M2/M3/M5 只按运行时能力检测兼容，不作为 MVP 强验收机器。

## 3. MVP 功能范围

MVP 只包含以下功能，页面需求不缩减：

1. 实时温度采集。
2. 菜单栏显示关键温度。
3. Popup 显示当前温度概览。
4. 主窗口展示温度 Dashboard。
5. 指标详情页展示温度趋势图。
6. 本地会话历史记录，记录范围为 MacWatch App 从本次打开到关闭这段时间。
7. 基础设置：刷新间隔、温度单位、趋势默认展示范围、菜单栏显示项。
8. 设备兼容性展示：显示每个温度指标是否可用、数据来源和失败原因。
9. 本地隐私保护：默认不联网、不上传、不记录用户内容。

### 3.1 Stats 复用策略

MVP 参考 `docs/origin/Stats复用策略.md`，采用“MacWatch 独立仓库 + Stats 作为只读 Git submodule + MacWatch 自己写 Adapter 层”的复用策略。

- `Vendor/Stats/` 作为只读上游源码依赖，当前固定版本为 `v3.0.1`。
- MacWatch 只通过 `StatsAdapter` 调用或包装 Stats 中必要的温度采集能力。
- 不复用 Stats UI、Remote、Updater、SystemStats、LevelDB 历史存储、通知、macOS Widget、风扇控制 helper。
- 不依赖 Stats 的 DB 策略。MacWatch 历史记录由 MacWatch 自己的 Core/Storage 负责。
- 默认禁用或隔离 Stats 中所有联网路径，MVP 首次启动和默认运行不得发起外部网络请求。

## 4. 明确不做的功能

MVP 不做以下功能：

- CPU 使用率、每核心使用率、CPU 负载历史。
- GPU 使用率、Renderer/Tiler 使用率、ANE 使用率。
- 内存使用率、内存压力、Swap 历史。
- 磁盘容量、磁盘读写速率、磁盘 I/O 历史。
- 电池电量曲线、电池健康趋势、充放电功率分析。
- 系统总功耗、CPU/GPU/ANE/RAM 功耗。
- 风扇转速、风扇异常判断、风扇控制。
- 温度阈值告警和系统通知。
- CSV/JSON 数据导出。
- 设置导入导出。
- 云同步、远程监控、多设备看板。
- 进程级统计和进程级长期历史。
- macOS 桌面 Widget。
- 蓝牙设备、电源适配器、网络、时钟等非温度核心模块。

## 5. 温度指标定义

### 5.1 指标级别

MVP 使用以下指标级别：

| 级别 | 含义 |
| --- | --- |
| 必需 | 在目标机型上必须实现采集、展示和历史记录 |
| 设备支持时展示 | 运行时检测到可读取时展示；不可读取时显示原因 |
| 后续 | 不进入 MVP，只保留扩展可能 |

### 5.2 MVP 温度指标

| 指标 | 级别 | 说明 |
| --- | --- | --- |
| CPU 温度 | 必需 | 在 MacBook Air M4 验收机上必须读取到有效 CPU 温度；优先展示最高 CPU 相关温度，可用时展示平均温度 |
| GPU 温度 | 设备支持时展示 | 设备支持时展示 GPU 温度；不可读取时必须在兼容性信息中说明 |
| 内存温度 | 设备支持时展示 | 设备支持时展示内存或 Memory Proximity 温度；不可读取时必须在兼容性信息中说明 |
| 内置 SSD/NAND 温度 | 设备支持时展示 | 优先读取内置存储温度；外接磁盘不进入 MVP；不可读取时必须在兼容性信息中说明 |
| 电池温度 | 设备支持时展示 | 来自电池相关系统信息；不可读取时必须在兼容性信息中说明 |
| 最高温度摘要 | 必需 | 在所有有效温度样本中计算当前最高温度 |
| 温度变化趋势 | 必需 | 对有效温度样本记录并展示曲线 |

### 5.3 指标状态

每个温度指标必须包含状态：

| 状态 | 含义 |
| --- | --- |
| valid | 读取成功，数值有效 |
| unsupported | 当前设备或系统不支持该指标 |
| readFailed | 理论上支持，但本次读取失败 |
| stale | 数据已过期，未在预期刷新窗口内更新 |

MVP 不使用 `estimated` 作为有效展示状态。若某指标无法读取，不得通过算法估算为真实温度。

## 6. 数据来源与兼容策略

### 6.1 数据来源优先级

MVP 可参考 Stats 的底层采集能力，但必须按 MacWatch 的温度专项需求收敛：

| 优先级 | 来源 | 用途 | MVP 策略 |
| --- | --- | --- | --- |
| 1 | HID Sensors | Apple Silicon 温度传感器 | 优先用于 M 系列 MacBook Air 的 CPU、GPU、SOC、内存、NAND、电池等可读温度 |
| 2 | SMC | 读取部分温度传感器 | HID 不可用或缺项时作为补充来源 |
| 3 | Battery IORegistry | 电池温度 | 电池温度优先使用该来源 |
| 4 | NVMe SMART | 内置 SSD/NAND 温度 | 设备支持时读取内置存储温度 |
| 候选 | IOReport Candidate | Apple Silicon 相关底层数据 | 仅作为候选来源，不作为 MVP 温度主来源承诺；必须源码验证到具体温度 channel 后才可作为有效来源 |

### 6.2 能力检测原则

- 应用启动时执行一次设备能力检测。
- 每类温度采集器独立判断可用性。
- 采集器失败不能影响其他采集器。
- 指标不可用时，UI 必须展示原因，不能显示 `0°C`、空白或上一次有效值作为当前值。
- 数据来源名称应在详情页展示，统一使用 `HID Sensors`、`SMC`、`Battery IORegistry`、`NVMe SMART`、`IOReport Candidate`。

### 6.3 传感器命名策略

Apple Silicon 传感器名称可能不稳定。MVP 不要求对每个底层 sensor key 做永久语义映射，但需要做到：

- 原始传感器 key 可追踪。
- UI 展示名称尽量友好，例如 CPU、GPU、内存、Battery、SSD/NAND、System。
- 无法确认语义的传感器归类为“其他系统温度”。
- 趋势历史中的指标名保持稳定，避免升级后旧数据无法查询。

## 7. 用户流程

### 7.1 首次启动

1. 应用启动并显示菜单栏图标。
2. 检测当前设备是否为 MacBook Air M 系列。
3. 检测可用温度采集器和温度指标。
4. 显示简短说明：MVP 仅监控本机温度，默认不联网。
5. 用户选择温度单位、菜单栏显示项和刷新间隔。
6. 应用创建新的本地会话历史，清空上次会话历史，并开始实时采集。

### 7.2 查看实时温度

1. 用户查看菜单栏温度摘要。
2. 点击菜单栏图标打开 Popup。
3. Popup 展示当前最高温度、CPU 温度、GPU、内存、磁盘、电池温度状态和数据更新时间。
4. 不支持的指标显示“不支持”或在兼容性区域说明。

### 7.3 查看温度趋势

1. 用户打开主窗口 Dashboard。
2. Dashboard 显示当前温度概览和最近趋势摘要。
3. 用户选择 CPU、GPU、内存、内置 SSD/NAND、电池或系统传感器。
4. 进入详情页查看最近 15 分钟、1 小时、6 小时或全会话温度曲线。
5. 用户可查看当前值、最高值、最低值、平均值和峰值时间。

## 8. 页面需求

### 8.1 菜单栏

菜单栏提供轻量实时入口。

功能点：

- 默认显示当前最高温度，例如 `72°C`。
- 支持切换显示最高温度、CPU 温度、GPU 温度、内存温度、磁盘温度或电池温度。
- 支持温度单位：摄氏度、华氏度。
- 数据过期时显示弱化状态，不继续显示为正常实时值。
- 点击打开 Popup。

验收标准：

- 默认刷新间隔为 5 秒。
- 菜单栏显示文本不超过 30 个字符。
- 菜单栏刷新不造成明显 UI 卡顿。

### 8.2 Popup 当前温度概览

Popup 用于快速查看当前温度状态。

功能点：

- 显示当前最高温度。
- 显示 CPU 温度。
- 显示 GPU、内存、内置 SSD/NAND、电池、系统温度；不可读取的指标显示状态说明，不作为有效温度显示。
- 显示每个指标的数据来源、更新时间和状态。
- 提供打开 Dashboard 的入口。
- 提供打开兼容性信息的入口。

验收标准：

- Popup 打开后 1 秒内显示最近一次有效采样。
- 不支持的指标不显示为有效温度。
- 读取失败的指标应显示失败状态。

### 8.3 Dashboard

Dashboard 是 MVP 的主窗口总览页。

功能点：

- 显示当前最高温度卡片。
- 显示 CPU、GPU、内存、内置 SSD/NAND、电池、系统温度卡片，按设备支持情况展示。
- 显示最近 1 小时温度趋势摘要。
- 显示可用温度指标数量和不可用指标说明。
- 支持进入单个指标详情页。

验收标准：

- Dashboard 首屏打开时间小于 1 秒。
- 指标卡片必须显示单位、更新时间、数据来源和状态。
- 对不可用指标明确显示原因，不出现误导性空值。

### 8.4 温度详情页

详情页用于查看某个温度指标的变化过程。

功能点：

- 显示当前值。
- 显示趋势图。
- 支持时间范围：最近 15 分钟、1 小时、6 小时、全会话。
- 显示最大值、最小值、平均值、峰值时间。
- 显示数据来源、采样间隔和最近读取状态。
- 支持曲线悬停查看时间点数值。

验收标准：

- 查询当前会话历史数据应在 1 秒内返回。
- 曲线单位和坐标轴准确显示。
- 数据缺口应在图表上体现，不能用连续线误导用户。

### 8.5 基础设置

MVP 设置页只包含温度监控必要配置。

功能点：

- 配置温度单位：摄氏度、华氏度。
- 配置实时刷新间隔：5 秒、10 秒、30 秒。
- 配置趋势默认展示范围：15 分钟、1 小时、6 小时、全会话。
- 配置菜单栏显示项：最高温度、CPU 温度、GPU 温度、内存温度、磁盘温度、电池温度。
- 查看设备兼容性状态。
- 手动清除当前会话历史数据。

验收标准：

- 设置修改后应立即生效，或明确提示需要重启。
- 清除历史数据需要二次确认。
- 重置设置不应默认删除当前会话历史数据。

## 9. 本地历史记录策略

### 9.1 历史记录目标

MVP 只记录温度指标，用于当前 App 运行会话内的趋势查看。历史记录不是完整遥测系统，也不用于长期设备健康分析。

每次 App 启动时创建新的本地会话历史，并清空上次会话历史。App 退出后，旧会话历史不参与下次启动后的趋势查看。历史数据保存到 MacWatch 自己的本地存储，不使用 Stats LevelDB 或 Stats DB 策略。

### 9.2 默认采样与写入策略

| 指标类型 | 实时刷新 | 历史写入 | 默认展示范围 |
| --- | --- | --- | --- |
| CPU 温度 | 5 秒 | 10 秒 | 全会话 |
| GPU 温度 | 5 秒 | 10 秒 | 全会话 |
| 内存温度 | 30 秒 | 60 秒 | 全会话 |
| 内置 SSD/NAND 温度 | 30 秒 | 60 秒 | 全会话 |
| 电池温度 | 30 秒 | 60 秒 | 全会话 |
| 系统温度传感器 | 10 秒 | 30 秒 | 全会话 |

用户可将趋势默认展示范围调整为最近 15 分钟、1 小时、6 小时或全会话。MVP 不提供跨会话保留设置。

### 9.3 数据模型需求

每条温度样本至少包含：

| 字段 | 说明 |
| --- | --- |
| 时间戳 | Unix epoch 毫秒 |
| 指标名 | 例如 `cpu.temperature.hottest` |
| 数值 | Double |
| 单位 | `°C` 或内部统一摄氏度 |
| 来源 | HID Sensors、SMC、Battery IORegistry、NVMe SMART、IOReport Candidate |
| 设备范围 | cpu、gpu、memory、ssd、battery、system、sensor |
| 设备标识 | 传感器 key 或内部稳定 ID |
| 质量状态 | valid、unsupported、readFailed、stale |

### 9.4 数据缺口

- 设备睡眠期间不补造数据。
- 唤醒后恢复采集，并记录新样本。
- 趋势图应显示缺口，避免把睡眠前后的数据直接连成连续变化。
- App 退出到下次启动之间不补造数据，也不把上一会话数据接入新会话曲线。

## 10. 非功能需求

### 10.1 性能

- 默认配置下应用自身平均 CPU 占用目标低于 2%。
- 默认配置下内存占用目标低于 120 MB。
- 菜单栏和 Popup 刷新不得阻塞主线程。
- 趋势图不得一次渲染过多点；全会话曲线可按展示宽度降采样。

### 10.2 能耗

- 默认不做高成本持续枚举。
- 传感器列表应缓存，只在启动、唤醒或间隔较长时刷新。
- 主窗口不可见时，UI 专用刷新降频。
- 设备使用电池供电时，不主动提高采样频率。

### 10.3 稳定性

- 任一采集器失败不应导致应用崩溃。
- 单个指标读取失败不影响其他温度指标。
- 睡眠和唤醒后采集应自动恢复。
- 历史数据库写入失败时，应继续提供实时显示，并记录错误状态。
- StatsAdapter 或单个 Stats 采集路径失败时，不应影响其他温度采集器。

### 10.4 隐私

- 默认不发起外部网络请求。
- 默认不上传任何硬件指标。
- 不记录用户文件名、网络访问内容、窗口标题、进程列表。
- 本地会话历史数据库保存在应用数据目录，并由 MacWatch 自己管理。
- Stats 中 Remote、SystemStats、Updater、外部 IP 查询等联网路径默认禁用或隔离。

## 11. 权限与安全

| 能力 | 是否需要用户授权 | MVP 策略 |
| --- | --- | --- |
| 温度基础采集 | 通常不需要 | 使用系统可读接口，失败时降级 |
| 电池温度读取 | 通常不需要 | 通过电池相关系统信息读取 |
| 内置 SSD 温度 | 可能受系统限制 | 设备支持时展示，不强制要求 |
| 通知权限 | 不需要 | MVP 不做告警通知 |
| 登录启动 | 可选，需要用户同意 | 可作为基础设置项，非核心验收 |
| 风扇控制 helper | 不需要 | MVP 不做 |
| 文件导出权限 | 不需要 | MVP 不做导出 |
| 外部网络访问 | 不需要 | MVP 默认禁用，不复用 Stats 联网能力 |

如后续版本引入 privileged helper、联网能力或导出能力，必须另行设计权限说明和用户确认流程。

## 12. 验收标准

### 12.1 核心功能验收

- 应用可在 MacBook Air M 系列设备上启动并显示菜单栏图标。
- 应用能检测当前设备是否属于 MVP 目标机型。
- 应用在 MacBook Air M4 验收机器上必须展示至少一个 `valid` 的 CPU 温度指标。
- 应用能展示所有可读取温度指标的当前值、单位、来源和状态。
- 应用能覆盖 CPU、GPU、内存、磁盘、电池五类硬件的温度状态展示；不可读取的类别必须显示不可用原因。
- 应用能记录并查询当前会话内的温度历史。
- 应用能按单个温度指标展示趋势图。
- 应用能显示数据缺口和读取失败状态。

### 12.2 兼容性验收

- 在无风扇 MacBook Air 上，不显示风扇相关功能。
- GPU、内存、内置 SSD/NAND、电池等温度不可读取时，显示“不支持”或“读取失败”，不显示伪造值，也不能从兼容性信息中消失。
- 不支持的指标不参与最高温度计算。
- 数据来源无法识别时，指标仍可归类为系统传感器并显示原始 key。
- 磁盘温度只覆盖内置 SSD/NAND，外接磁盘、扩展坞磁盘和外置存储不进入 MVP。
- IOReport 只能作为 `IOReport Candidate` 候选来源；未经源码验证到具体温度 channel 时，不能作为有效温度来源展示。

### 12.3 性能与能耗验收

- 默认刷新配置下，应用自身平均 CPU 占用目标低于 2%。
- Dashboard 首屏打开时间小于 1 秒。
- 当前会话趋势查询小于 1 秒。
- 应用连续运行一个完整工作日不崩溃。
- 睡眠唤醒后采集自动恢复。

### 12.4 隐私验收

- 首次启动和默认运行不发起任何外部网络请求。
- 本地会话历史数据只包含温度指标、时间戳、来源和设备范围。
- 不记录文件路径、窗口标题、网络内容或进程列表。
- 不复用 Stats Remote、SystemStats、Updater 或外部 IP 查询能力。

## 13. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| Apple Silicon 传感器 key 不稳定 | 指标命名和归类困难 | 保留原始 key，使用稳定内部指标名和兼容性说明 |
| 某些温度来源不可读取 | 指标缺失 | 设备支持时展示，不把不可用指标作为失败 |
| 内存温度不稳定或不可读 | 无法展示内存温度 | 明确显示“不支持内存温度读取”或读取失败原因 |
| 内置 SSD/NAND 温度读取受限制 | 无法展示磁盘温度 | 明确显示“不支持内置存储温度读取” |
| 高频采样增加能耗 | 影响续航 | 默认 5 秒或更低频刷新，历史写入低于实时刷新 |
| 睡眠导致数据缺口 | 趋势图不连续 | 显示缺口，不补造数据 |
| Stats 采集实现迁移复杂 | MVP 延期 | 只通过 StatsAdapter 复用温度采集必要路径，暂不迁移完整模块体系 |
| Stats 联网或历史路径误接入 | 违反本地隐私和历史策略 | 禁用或隔离 Remote、SystemStats、Updater、LevelDB/DB 等非采集路径 |

## 14. MVP 成功指标

- 用户可以在菜单栏看到当前最高温度。
- 用户可以在 Popup 中查看 CPU、GPU、内存、磁盘、电池的当前温度或不可用原因。
- 用户可以在主窗口查看当前会话内的温度趋势。
- 应用能清楚说明哪些温度指标可用、不可用以及原因。
- 应用默认轻量运行，不明显影响 MacBook Air 续航。
- 应用默认本地运行，不上传任何数据。
