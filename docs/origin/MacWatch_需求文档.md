# MacWatch 项目需求文档

文档版本：v1.0  
项目名称：MacWatch  
目标平台：macOS 12 Monterey 及以上  
参考项目：Stats 源码  
编写日期：2026-06-08

## 1. 背景

MacWatch 是一个面向 macOS 的本地硬件与系统资源监控工具。项目目标是在菜单栏和主窗口中实时展示电脑的 CPU、电池、硬盘等硬件温度变化，以及 CPU、内存、磁盘等硬件资源使用情况变化，并将关键指标持续记录为历史数据，方便用户回看、分析和导出。

参考项目 Stats 已实现较完整的 macOS 菜单栏系统监控能力，覆盖 CPU、GPU、内存、磁盘、网络、电池、传感器、蓝牙、时钟、远程监控等模块。MacWatch 将基于 Stats 的模块化设计和底层采集能力进行开发，但产品重点从“实时菜单栏展示”转向“实时监控 + 长期记录 + 趋势分析 + 异常告警”。

## 2. 产品定位

MacWatch 定位为 macOS 本地硬件状态监控与历史分析工具。

核心价值：

- 实时查看 CPU、内存、磁盘、电池、温度、风扇等状态。
- 记录关键硬件指标随时间变化的过程。
- 通过趋势图定位过热、资源异常、耗电异常、磁盘 I/O 异常。
- 在温度、电池、磁盘空间、资源占用等指标异常时发出本地提醒。
- 默认本地保存数据，不上传用户设备指标。

## 3. 目标用户

| 用户类型 | 需求 |
| --- | --- |
| 普通 Mac 用户 | 了解电脑温度、电池健康、内存压力和磁盘空间，及时发现异常 |
| 开发者 | 在编译、运行容器、虚拟机、大型 IDE 时观察 CPU、内存、温度和风扇变化 |
| 内容创作者 | 在视频剪辑、渲染、转码时观察 CPU/GPU 温度、功耗、磁盘 I/O |
| 运维/测试人员 | 记录长时间压测过程中的硬件资源曲线与异常事件 |
| 硬件维护人员 | 辅助分析电池老化、硬盘温度、散热异常和风扇状态 |

## 4. 项目目标

### 4.1 MVP 目标

MVP 必须实现以下能力：

1. 菜单栏实时监控。
2. CPU 使用率、CPU 温度、CPU 负载历史记录。
3. 内存使用率、内存压力、Swap 历史记录。
4. 磁盘容量、磁盘读写速率、硬盘温度历史记录。
5. 电池电量、电池温度、电池健康、充放电状态历史记录。
6. 传感器温度、风扇转速、系统功耗历史记录。
7. 主窗口 Dashboard 展示实时状态和趋势摘要。
8. 指标详情页展示时间范围趋势图。
9. 异常阈值告警。
10. 本地历史数据存储、查询、清理和导出。
11. 基础设置：启动项、采样间隔、温度单位、数据保留周期、告警阈值。

### 4.2 非 MVP 目标

以下功能不纳入第一版，但保留架构扩展能力：

- 远程监控。
- 云同步。
- 蓝牙外设电量监控。
- 多时区时钟。
- 风扇手动控制。
- macOS 桌面 Widget。
- 进程级长期历史。
- 多设备统一看板。

### 4.3 明确不做或默认关闭

第一版不默认提供以下能力：

- 不默认上传任何硬件指标到外部服务。
- 不默认控制风扇转速。
- 不默认持续运行高成本传感器扫描。
- 不记录用户文件名、网络访问内容、窗口标题等隐私信息。

## 5. 与 Stats 的功能关系

Stats 已实现的能力可分为三类：复用、改造、暂缓。

| Stats 功能 | MacWatch 处理方式 | 说明 |
| --- | --- | --- |
| CPU 使用率、温度、频率、Top 进程 | 复用并增强 | 增加长期历史与趋势分析 |
| RAM 使用、内存压力、Swap | 复用并增强 | 增加压力持续时间和历史查询 |
| Disk 容量、I/O、SMART 温度 | 复用并增强 | 增加磁盘温度和 I/O 历史 |
| Battery 电量、健康、温度、功耗 | 复用并增强 | 增加电池温度和充放电曲线 |
| Sensors 温度、电压、电流、功率、风扇 | 重点复用 | MacWatch 的核心采集来源 |
| GPU 使用率、温度、功耗 | MVP 可选，MVP+ 纳入 | 对 Apple Silicon 有重要价值 |
| Network | 可选 | 非核心硬件温度需求 |
| Bluetooth | 暂缓 | 与核心目标弱相关 |
| Clock | 暂缓 | 与核心目标无直接关系 |
| Remote | 暂缓 | 涉及隐私与账号体系 |
| LevelDB 短期历史 | 不作为主库 | 改为 SQLite/GRDB 长期历史 |
| 菜单栏 Widget | 复用设计思想 | 保留轻量实时入口 |
| 通知 | 复用设计思想 | 扩展为告警事件系统 |

## 7. 功能需求

## 7.1 菜单栏实时监控

### 需求描述

MacWatch 应在 macOS 菜单栏提供轻量实时监控入口。用户无需打开主窗口即可查看关键状态。

### 功能点

- 支持显示 CPU 使用率。
- 支持显示 CPU 温度或最高温度。
- 支持显示内存使用率或内存压力。
- 支持显示磁盘可用空间或磁盘 I/O。
- 支持显示电池电量、电池温度或充放电状态。
- 支持显示风扇转速或系统温度。
- 支持用户选择菜单栏显示的指标。
- 支持点击菜单栏打开 Popup 概览。
- 支持双击或菜单项打开主 Dashboard。

### 验收标准

- 菜单栏指标在默认 2 秒至 5 秒内刷新。
- 菜单栏显示不应造成明显卡顿。
- 用户关闭某类指标后，对应高成本采集应暂停或降频。

## 7.2 主 Dashboard

### 需求描述

主 Dashboard 是 MacWatch 的核心总览页面，用于展示当前硬件状态、近期趋势和异常状态。

### 功能点

- 显示当前 CPU 使用率、CPU 温度、CPU 负载。
- 显示当前内存使用率、内存压力、Swap 使用。
- 显示当前磁盘使用率、读写速率、硬盘温度。
- 显示当前电池电量、电池温度、电池健康。
- 显示当前风扇转速、系统功耗、关键传感器温度。
- 显示最近 1 小时趋势摘要。
- 显示当前告警和最近异常事件。
- 支持进入每类指标详情页。

### 验收标准

- Dashboard 首屏打开时间应小于 1 秒。
- 指标卡片应明确标识单位、更新时间、数据来源状态。
- 不支持的指标应显示“当前设备不支持”，不能显示误导性空值。

## 7.3 指标详情与历史趋势

### 需求描述

用户可以查看任一指标在指定时间范围内的变化曲线，用于分析温度、负载、耗电、磁盘 I/O 等变化过程。

### 功能点

- 支持按指标查看趋势图。
- 支持时间范围：最近 15 分钟、1 小时、6 小时、24 小时、7 天、30 天、自定义。
- 支持显示最大值、最小值、平均值、当前值。
- 支持曲线缩放和悬停查看时间点数值。
- 支持多指标叠加，例如 CPU 使用率 + CPU 温度，电池电量 + 电池温度。
- 支持异常事件标记，例如温度超过阈值、磁盘空间不足、内存压力过高。
- 支持按采样粒度聚合：原始数据、分钟平均、小时平均、日平均。

### 验收标准

- 查询最近 24 小时数据应在 1 秒内返回。
- 查询 30 天数据应使用聚合数据或降采样，不应直接渲染过多点导致卡顿。
- 曲线单位和坐标轴应准确显示。

## 7.4 历史记录

### 需求描述

MacWatch 应持续记录关键指标，形成本地时间序列数据。

### 功能点

- 支持实时采样和历史落库解耦。
- 支持每个指标独立采样间隔。
- 支持每个指标独立历史写入间隔。
- 支持设备进入睡眠、唤醒后的采集恢复。
- 支持记录数据缺口，例如睡眠期间无数据。
- 支持数据压缩或降采样。
- 支持保留周期设置：7 天、30 天、90 天、180 天、永久。
- 支持手动清除历史数据。

### 默认策略

| 指标类型 | 实时刷新 | 历史写入 | 说明 |
| --- | --- | --- | --- |
| CPU 使用率 | 1-2 秒 | 5 秒 | 高频变化指标 |
| CPU 温度 | 2-5 秒 | 10 秒 | 温度变化不需每秒落库 |
| 内存使用 | 2-5 秒 | 10 秒 | 中频指标 |
| 磁盘 I/O | 1-2 秒 | 5 秒 | 高频变化指标 |
| 磁盘容量 | 30-60 秒 | 60 秒 | 低频指标 |
| 电池状态 | 10-30 秒 | 30 秒 | 低频指标，电源事件触发时立即写入 |
| 电池温度 | 10-30 秒 | 30 秒 | 低频指标 |
| 风扇转速 | 2-5 秒 | 10 秒 | 中频指标 |
| 系统功耗 | 2-5 秒 | 10 秒 | 中频指标 |

### 验收标准

- 退出应用后再次启动，历史数据仍可查询。
- 应用异常退出后，不应损坏历史数据库。
- 数据清理策略应可配置且可验证。

## 7.5 温度监控

### 需求描述

温度监控是 MacWatch 的核心能力。系统应统一展示 CPU、电池、硬盘、GPU、系统传感器等温度变化。

### 功能点

- 支持 CPU 平均温度和最高温度。
- 支持电池温度。
- 支持硬盘温度，设备支持 SMART 或传感器时展示。
- 支持 GPU 温度，设备支持时展示。
- 支持系统传感器温度列表。
- 支持温度单位：摄氏度、华氏度。
- 支持温度阈值告警。
- 支持温度趋势图。
- 支持温度异常事件记录。
- 支持显示数据来源：SMC、HID、IOReport、SMART、Battery IORegistry。

### 验收标准

- 不同来源的温度指标应有统一单位。
- 无法读取的温度指标不得伪造或估算为有效值。
- 温度超过阈值时应触发本地通知，并记录事件。

## 7.6 告警与通知

### 需求描述

MacWatch 应根据用户配置的阈值对异常指标发出提醒。

### 功能点

- 支持 CPU 温度过高告警。
- 支持电池温度过高告警。
- 支持硬盘温度过高告警。
- 支持内存压力过高告警。
- 支持磁盘空间不足告警。
- 支持风扇转速异常告警。
- 支持电池健康低于阈值告警。
- 支持 CPU 使用率持续过高告警。
- 支持告警冷却时间，避免重复提醒。
- 支持告警恢复事件记录。
- 支持按指标启用/禁用告警。

### 默认阈值建议

| 告警项 | 默认阈值 | 持续时间 | 说明 |
| --- | --- | --- | --- |
| CPU 温度高 | 90°C | 60 秒 | 不同机型可调整 |
| 电池温度高 | 40°C | 60 秒 | 保守阈值 |
| 硬盘温度高 | 60°C | 120 秒 | SSD/HDD 差异较大，允许用户调整 |
| 内存压力高 | Warning 或 Critical | 60 秒 | 基于系统压力等级 |
| 磁盘空间不足 | 可用空间 < 10% | 300 秒 | 按卷判断 |
| CPU 使用率持续高 | > 90% | 300 秒 | 避免短时峰值误报 |
| 风扇异常 | 转速为 0 且温度持续升高 | 120 秒 | 仅有风扇设备启用 |

### 验收标准

- 告警触发、恢复、忽略都应记录到事件表。
- 用户关闭某类告警后，不应再收到该类通知。
- 告警通知文案应包含指标、当前值、阈值、持续时间。

## 7.7 数据导出

### 需求描述

用户应能够导出历史数据，用于分析、归档或提交问题报告。

### 功能点

- 支持按时间范围导出。
- 支持按指标类型导出。
- 支持 CSV 格式。
- 支持 JSON 格式。
- 支持导出设备概况。
- 支持导出告警事件。
- 支持隐藏设备序列号等敏感信息。

### 验收标准

- 导出的 CSV 应包含时间戳、指标名、数值、单位、设备/磁盘标识、数据源。
- 导出过程不应阻塞 UI。
- 导出大范围数据时应显示进度。

## 7.8 设置

### 需求描述

设置页用于管理采样、展示、告警、数据保留、启动行为等。

### 功能点

- 启用/禁用模块：CPU、内存、磁盘、电池、传感器、GPU、网络。
- 配置菜单栏显示指标。
- 配置采样间隔和历史写入间隔。
- 配置温度单位。
- 配置数据保留周期。
- 配置告警阈值和冷却时间。
- 配置登录启动。
- 配置 Dock 图标显示。
- 导入/导出应用设置。
- 清理历史数据。
- 查看传感器兼容性状态。

### 验收标准

- 设置修改后应立即生效或明确提示需要重启。
- 设置导出不应包含敏感 token 或设备唯一标识，除非用户明确选择。
- 重置设置不应默认删除历史数据，需单独确认。

## 7.9 设备兼容性展示

### 需求描述

不同 Mac 型号、CPU 架构和 macOS 版本对传感器读取支持不同。MacWatch 应清晰展示兼容性状态。

### 功能点

- 显示设备型号、芯片架构、macOS 版本。
- 显示各采集器状态：可用、不可用、权限不足、读取失败。
- 显示每个温度指标的数据来源。
- 对不可用指标提供原因说明。
- 支持导出兼容性诊断报告。

### 验收标准

- 在无电池的 Mac 上，电池模块应自动隐藏或标记不可用。
- 在不支持硬盘温度的磁盘上，应显示“不支持 SMART 温度读取”。
- 在无风扇设备上，不应显示风扇异常告警。

## 7.10 隐私与安全

### 需求描述

MacWatch 默认只在本地处理和保存硬件指标，不上传用户数据。

### 功能点

- 默认不启用远程监控。
- 默认不上传硬件指标。
- 默认不记录文件路径、网络访问内容、窗口标题。
- 导出数据前提示可能包含设备型号、磁盘名称等信息。
- 如后续提供远程监控，必须由用户显式开启。
- 如使用 privileged helper，必须说明用途并限制为必要能力。

### 验收标准

- 首次启动不应发起非必要外部网络请求。
- 用户禁用联网功能后，不应访问外部 API。
- 历史数据库保存在本机应用数据目录。

## 8. 非功能需求

## 8.1 性能

- 菜单栏实时刷新不应造成 UI 卡顿。
- 默认配置下，MacWatch 自身 CPU 占用平均应低于 2%。
- 默认配置下，MacWatch 内存占用应控制在合理范围，目标低于 150 MB。
- 历史写入应批量进行，避免频繁磁盘写。
- 趋势图应采用降采样或聚合查询，避免一次渲染过多数据点。

## 8.2 能耗

- 默认禁用高成本采集器或降低采样频率。
- 当 Popup、主窗口、详情页不可见时，UI 专用采集应降频。
- 设备使用电池供电时，可提供低功耗模式。
- 传感器扫描不应每次都重新枚举，应该缓存传感器列表并周期性刷新。

## 8.3 稳定性

- 任一采集器失败不应导致应用崩溃。
- 数据库写入失败应记录错误并降级为实时显示。
- 睡眠/唤醒后采集器应自动恢复。
- 应用重启后应恢复用户配置。

## 8.4 可维护性

- 采集器应有统一协议和清晰边界。
- 指标命名应统一，避免 UI 直接依赖底层数据结构。
- 数据库 schema 应有版本迁移机制。
- 设备兼容逻辑应集中管理。

## 8.5 兼容性

- 支持 macOS 12 Monterey 及以上。
- 支持 Intel Mac 和 Apple Silicon Mac。
- 对 Apple Silicon 不同芯片系列应按能力检测，而不是硬编码假设。
- 对无电池、无风扇、无独立 GPU 的设备应优雅降级。

## 9. 数据保留策略

默认数据保留建议：

| 数据类型 | 默认保留 | 说明 |
| --- | --- | --- |
| 高频原始数据 | 7 天 | CPU、I/O、风扇、功耗等 |
| 中频原始数据 | 30 天 | 温度、电池、内存等 |
| 分钟聚合数据 | 90 天 | min/max/avg/count |
| 小时聚合数据 | 1 年 | 趋势分析 |
| 告警事件 | 1 年 | 体积小，价值高 |
| 设备档案 | 永久 | 直到用户清除 |

用户可在设置中修改保留周期。永久保留需要提示磁盘空间占用风险。

## 10. 用户流程

## 10.1 首次启动

1. 应用启动并显示菜单栏图标。
2. 自动检测设备能力：CPU、内存、磁盘、电池、传感器、风扇、GPU。
3. 展示初始设置向导。
4. 用户选择是否登录启动、温度单位、默认监控指标和数据保留周期。
5. 应用开始采集并记录历史。

## 10.2 查看实时状态

1. 用户查看菜单栏指标。
2. 点击菜单栏打开 Popup。
3. Popup 展示当前 CPU、温度、内存、磁盘、电池摘要。
4. 用户点击某个指标进入详情页。

## 10.3 分析历史趋势

1. 用户打开主 Dashboard。
2. 选择 CPU 温度或硬盘温度。
3. 选择最近 24 小时或自定义时间范围。
4. 查看趋势图、峰值、均值和异常事件。
5. 可叠加 CPU 使用率与温度进行关联分析。

## 10.4 处理告警

1. 指标超过阈值并持续达到指定时间。
2. 系统发出本地通知。
3. MacWatch 记录告警事件。
4. 用户点击通知进入相关指标详情页。
5. 指标恢复正常后记录恢复事件。

## 10.5 导出数据

1. 用户进入导出页面。
2. 选择时间范围和指标类型。
3. 选择 CSV 或 JSON。
4. 选择是否包含设备档案和告警事件。
5. 导出文件到用户指定位置。

## 11. 页面需求

## 11.1 菜单栏

菜单栏应支持以下展示：

- 单指标显示：例如 CPU 42%、CPU 72°C、RAM 68%。
- 多指标组合显示：例如 CPU 42% / 72°C。
- 图形显示：迷你折线图、柱状图、状态点。
- 告警状态：异常时高亮或显示状态图标。

## 11.2 Popup 概览

Popup 应包含：

- 当前 CPU 使用率和温度。
- 当前内存使用和压力。
- 当前磁盘空间与 I/O。
- 当前电池状态和温度。
- 当前风扇转速和系统功耗。
- 最近告警。
- 打开 Dashboard 按钮。

## 11.3 Dashboard

Dashboard 应包含：

- 总览卡片。
- 最近 1 小时趋势摘要。
- 当前异常列表。
- 设备信息摘要。
- 指标详情入口。

## 11.4 指标详情页

指标详情页应包含：

- 当前值。
- 趋势图。
- 时间范围选择。
- 统计信息：最大、最小、平均、峰值时间。
- 告警事件标记。
- 数据来源和采样状态。

## 11.5 设置页

设置页应包含：

- 常规设置。
- 菜单栏设置。
- 模块设置。
- 采样与存储设置。
- 告警设置。
- 导入导出设置。
- 兼容性与诊断。

## 12. 数据模型需求

MacWatch 应设计统一指标模型，所有采样数据至少包含：

| 字段 | 说明 |
| --- | --- |
| 时间戳 | Unix epoch 毫秒或 ISO8601 |
| 指标名 | 统一命名，例如 `cpu.temperature.hottest` |
| 数值 | Double |
| 单位 | `%`、`°C`、`bytes/s`、`rpm`、`W` 等 |
| 来源 | SMC、IOKit、IOReport、sysctl、SMART 等 |
| 设备范围 | system、disk、battery、sensor、core 等 |
| 设备标识 | 磁盘 UUID、传感器 key、核心编号等，可为空 |
| 质量状态 | valid、unsupported、permissionDenied、readFailed、estimated |

## 13. 权限需求

| 能力 | 是否需要用户授权 | 说明 |
| --- | --- | --- |
| CPU/RAM 基础采集 | 否 | 使用系统 API |
| 电池基础采集 | 否 | 使用 IOPowerSources 和 IORegistry |
| 磁盘容量 | 否 | 普通文件系统 API |
| 磁盘 SMART | 可能需要更高权限或设备支持 | 依赖设备和系统限制 |
| SMC 读取 | 通常不需要管理员权限 | 但不同系统版本可能有差异 |
| 风扇控制 | 需要 privileged helper | MVP 不做 |
| 登录启动 | 需要用户同意 | 使用 Login Item |
| 通知 | 需要通知授权 | 用于告警 |
| 导出文件 | 需要用户选择路径 | 使用系统保存面板 |

## 14. 验收标准

## 14.1 核心功能验收

- 应用可在 macOS 12 及以上启动并显示菜单栏图标。
- CPU、内存、磁盘、电池至少四类模块可正常采集。
- 支持 CPU 温度、电池温度、硬盘温度在设备支持时采集和展示。
- 支持至少 24 小时历史记录查询。
- 支持按指标查看趋势图。
- 支持温度阈值告警。
- 支持 CSV 导出。

## 14.2 可靠性验收

- 应用运行 24 小时不崩溃。
- 睡眠唤醒后采集自动恢复。
- 数据库写入失败不会导致应用崩溃。
- 不支持的传感器不会导致空指针或误报。

## 14.3 性能验收

- 默认配置下应用自身平均 CPU 占用低于 2%。
- Dashboard 打开时间小于 1 秒。
- 最近 24 小时趋势查询小于 1 秒。
- 历史数据库 30 天默认数据不应造成明显 UI 卡顿。

## 16. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 不同 Mac 传感器 key 差异大 | 温度指标缺失或命名混乱 | 复用 Stats 传感器表，增加兼容性诊断和数据来源标识 |
| Apple Silicon 与 Intel 数据来源不同 | 采集器复杂度高 | 使用能力检测和平台策略模式 |
| SMART 温度不可用 | 硬盘温度无法显示 | 明确显示“不支持”，不做伪造值 |
| 高频采样增加能耗 | 用户体验下降 | 默认合理采样间隔，窗口不可见时降频，支持低功耗模式 |
| 长期历史数据库膨胀 | 占用磁盘空间 | 降采样、保留策略、定期清理 |
| 风扇控制存在设备风险 | 安全和责任问题 | MVP 只读，不做风扇控制 |
| 外部 API 涉及隐私 | 用户信任风险 | 默认本地运行，联网功能显式授权 |
| Stats 代码许可和后续升级 | 合规和维护风险 | 保留开源许可证声明，记录改造点 |

## 17. 成功指标

- 用户可以在菜单栏直接看到关键硬件状态。
- 用户可以回看至少 24 小时的温度和资源使用变化。
- 用户可以定位 CPU 高负载与温度升高的时间关系。
- 用户可以查看电池温度、电量、健康随时间变化。
- 用户可以发现磁盘空间不足、温度过高、内存压力过高等异常。
- 应用默认运行轻量、稳定、隐私友好。
